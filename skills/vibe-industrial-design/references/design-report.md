# The ID report and the version loop

Two artefacts, one authority.

## `design-report.md` — the authority

```
> Status block: date, version, what this is (ID/CMF/manufacturability study),
>   what it is NOT (structure, contracts), which contract wins on conflict.
0  Reference basis
   0.1 per-version change list  (#, change, v(n−1) → v(n), pixel evidence, why)
       + "not decided by the picture" list handed to the owner
1  ID   1.1 positioning + placement principles (e.g. "front carries one action")
        1.2 form language (the 4–5 rules a modeller must not break)
        1.3 overall dimensions table  (value + provenance tag)
        1.4 face → element allocation table
        1.5 per-element table per face (size · position · basis)
        1.6 human factors check (reach, sightlines at mounting height, night, cleaning)
2  CMF  2.1 palette (rendered hex · real-world start point (Pantone/RAL) · gloss/process)
        2.2 parts × material × finish (one row per material in the ledger)
        2.3 optics (colour temperature, uniformity, light-guide sandwich)
        2.4 marks / silk
3  Small-batch manufacturing
        3.1 tiers A (5–20, SLA + paint) / B (50–200, vacuum casting) / C (500+, soft tool)
        3.2 A-tier execution (steps, small-hole rule, ±0.2 tolerance, movers in MJF/POM,
            UV post-cure before paint) + per-unit parts list + consumables/fixtures
        3.3 feature notes (perforated grille options, button stack, light bar, IR window…)
        3.4 finishing, 3.5 assembly & mounting, 3.6 cost/lead-time orders of magnitude,
        3.7 risks R1… with the test that retires each
4  Open questions Q1… (things only the owner can decide: element existence, driver
   channels, a button diameter vs. a hand)
5  Next steps
```

Rules: numbers in the tables **equal `params.js`** (tag them). Cost is orders of
magnitude unless quoted. Say plainly what is not verified.

## `release/CC-…-<version>.docx` — the snapshot

Generated by a committed script (python-docx). Mirror the md section-for-section:
cover (brand, product, "ID <version>", date, hero render, scope disclaimer, a bold
"what changed since v(n−1)" paragraph) → 1 overview → 2 form (dimension table, six-face
allocation, contact sheet, front layout table, **change list vs. previous**) → 3
controls (one subsection per element, with the Blender shot) → 4 CMF → 5
manufacturing (tiers, A-tier plan, parts list, consumables, B/C summary, risk list) →
6 appendix (assets & toolchain, open questions, **version log table**).

Practicalities: set `w:eastAsia` on runs (CJK falls back to a serif otherwise); embed
the 10 MB contact sheet as a resized JPEG (13 MB → 2.7 MB); keep older versions in
`release/`; the script's `VERSION`/`DATE` constants and the tables are the only edits
between versions.

## The version loop (owner sends a new look image)

1. Save it: `refs/NN-<version>-<view>.png`. Cite it in `params.js`.
2. Measure (`references/reference-image-measurement.md`). Write pixel evidence into
   the params comments; add a `[vN]` tag description at the top of the file.
3. Change only what the picture shows. Faces not in the picture keep v(n−1) and the
   report says so.
4. Re-render the raster sheet and the Blender shot set; keep finals in
   `renders/`, everything else in the ignored `out/`.
5. Report: add the change list (§0.1), update the tables, update/append open questions
   (a picture that shrinks the button re-opens the finger question; a picture that adds
   14 LEDs opens the driver-channel question; a moved sensor window goes on the board
   respin list).
6. Regenerate the docx; append the version-log row; commit with the renders.
7. Ask the owner the open questions — a picture is not a decision on the things it
   doesn't show.
